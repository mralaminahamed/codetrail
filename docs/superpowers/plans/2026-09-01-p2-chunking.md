# codetrail P2 — AST chunking, embeddings, spans, window fallback

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the files P1 records into **spans** — one per top-level Go declaration, fixed windows everywhere else — give each an embedding, and persist them so P3 has something to retrieve and P6 has two arms to compare.

**Architecture:** A new `packages/shared/chunk` takes one file's bytes and a `Strategy` (`AST` or `Window`) and returns line-delimited chunks. Doc-comment stripping is a *source pre-pass* (`chunk.StripDocs`) applied before either strategy, so the eval's two arms chunk byte-identical input and `Window` still never parses. A new `packages/shared/embed` defines an `Embedder` interface with an Ollama implementation and a deterministic fake; CI uses the fake. `store.PutSpans` writes the spans and their `vector(768)` embeddings. The indexer wires it in after the walk, behind one per-job deadline.

**Tech Stack:** Go 1.27, `go/parser` + `go/ast` (standard library, no type information), pgx v5, Postgres 17 + pgvector, zerolog. **No new third-party dependencies.** The Ollama client is `net/http` + `encoding/json`; vectors are sent as pgvector's text literal with an explicit `::vector` cast, so no pgvector Go binding is needed.

**Spec:** `docs/superpowers/specs/2026-08-31-codetrail-design.md` — read **§5 (chunking)** first, then **§8–§9 (the eval, which constrains §5 in a way that is easy to miss)**, then §3 (data model) and §13 (phases). Read §5's doc-comment section twice: it is the reason this phase has a `StripDocs` function at all.

**Predecessor:** `docs/superpowers/plans/2026-08-31-p1-ingestion.md`. P1 merged at `77cc7ce`. This plan matches its shape deliberately.

## How to mutate, and what counts as a kill

P1 ran ~200 mutations across 8 tasks and the implementers found four defects **in the plan**. These rules exist because of those four. Read them before Task 1's mutation step, not after.

1. **Commit before you mutate.** Every mutation is reverted with `git checkout -- <file>`, which restores from `HEAD`. A P1 harness mutated against an uncommitted tree, so `git checkout` restored the *mutant* and nine kills were phantom. Run `git status --porcelain` and confirm it is empty before the first `sed`.
2. **A mutation that only breaks the build is a weak kill.** After applying one, run `go build ./... && go vet ./...`. If either fails, the mutation is testing the compiler. Rewrite it so it compiles and vets, then run the tests. P1 scored two kills that were really unbound query parameters producing a protocol error.
3. **Name the expected failure before you run it.** Every mutation below states which test must fail *and what the failure message looks like*. If the observed failure is a `t.Fatal(err)` on the way to the assertion, or a panic, or a `nil` dereference, **the kill does not count** — the test failed on an incident, not on its claim. P1 had a symlink test that died on `read repo/etc: is a directory` before reaching its own assertion; it looked like a kill and proved nothing. Fix the test so the assertion is what fails, then re-run.
4. **If you cannot describe the failing output, the test is not evidence.** P1 had a prescribed concurrency test that could not fail under its mutant. Before writing a test, say out loud what the failure looks like. If the answer is "it would hang" or "it would be flaky", redesign it so the failure is a comparison against a value.
5. **Mutate the wiring too.** Constructors and `main()` were P1's blind spot: mutation coverage only covers what you point it at. Task 6 mutates the wiring on purpose — the default strategy, the `CheckDim` call, the stripped-vs-unstripped source, the deadline.
6. **A comment claiming safety is the highest-risk line in the file.** P1 corrected **12 false comments across 7 tasks, every one a justification for why something was safe or unnecessary** — two of them introduced by commits *fixing* other false comments, and the last by a ruling that argued instead of measuring. Wherever this plan says "record why", the rule is: **run the counterfactual first, paste the observed output into the commit message, and only then write the comment.** If the counterfactual passes, the claim is false — delete it rather than rephrasing it.

import (
	"strconv"
	"strings"
	"testing"

func lines(n int) []byte {
	var b strings.Builder
	for i := 1; i <= n; i++ {
		b.WriteString("line")
		b.WriteString(strconv.Itoa(i))
		b.WriteByte('\n')
	}
	return []byte(b.String())
}

func winOpts(size, overlap int) Options {
	o := Defaults()
	o.Strategy = StrategyWindow
	o.WindowLines, o.WindowOverlap = size, overlap
	return o
}

// Every window is 1-based inclusive and covers exactly the lines it names.
// Anchored on content, not on arithmetic: a uniform off-by-one moves the text
// with the range and would survive a text-equals-slice check.
func TestWindowRangesAreOneBasedInclusive(t *testing.T) {
	src := lines(10)
	got, err := Chunks("a.txt", src, winOpts(4, 1))
	if err != nil {
		t.Fatal(err)
	}
	if got[0].StartLine != 1 {
		t.Fatalf("first window starts at %d, want 1", got[0].StartLine)
	}
	if first := strings.SplitN(got[0].Text, "\n", 2)[0]; first != "line1" {
		t.Fatalf("line %d holds %q, want line1", got[0].StartLine, first)
	}
	last := got[len(got)-1]
	if last.EndLine != 10 {
		t.Fatalf("last window ends at %d, want 10", last.EndLine)
	}
	tail := strings.Split(strings.TrimRight(last.Text, "\n"), "\n")
	if tail[len(tail)-1] != "line10" {
		t.Fatalf("line %d holds %q, want line10", last.EndLine, tail[len(tail)-1])
	}
	for _, c := range got {
		if c.EndLine-c.StartLine+1 != len(strings.Split(strings.TrimRight(c.Text, "\n"), "\n")) {
			t.Fatalf("%d..%d does not hold that many lines: %q", c.StartLine, c.EndLine, c.Text)
		}
	}
}

// Overlap is what stops a declaration cut in half from being unretrievable in
// both halves. Two adjacent windows must share exactly WindowOverlap lines.
func TestWindowsOverlapByExactlyTheConfiguredLines(t *testing.T) {
	got, err := Chunks("a.txt", lines(20), winOpts(5, 2))
	if err != nil {
		t.Fatal(err)
	}
	if len(got) < 3 {
		t.Fatalf("want several windows, got %d", len(got))
	}
	for i := 1; i < len(got); i++ {
		shared := got[i-1].EndLine - got[i].StartLine + 1
		if shared != 2 {
			t.Fatalf("windows %d and %d share %d lines, want 2", i-1, i, shared)
		}
	}
}

// The whole file is covered: the baseline arm's claim is that it indexes
// everything, so a gap between windows would be a silently unindexed region.
func TestWindowsCoverEveryLine(t *testing.T) {
	for _, n := range []int{1, 4, 5, 6, 19, 20, 21} {
		got, err := Chunks("a.txt", lines(n), winOpts(5, 2))
		if err != nil {
			t.Fatal(err)
		}
		covered := map[int]bool{}
		for _, c := range got {
			for l := c.StartLine; l <= c.EndLine; l++ {
				covered[l] = true
			}
		}
		for l := 1; l <= n; l++ {
			if !covered[l] {
				t.Fatalf("%d lines: line %d is in no window", n, l)
			}
		}
		if covered[n+1] {
			t.Fatalf("%d lines: a window runs past the end", n)
		}
	}
}

// A trailing window wholly inside its predecessor is a duplicate document with
// a different id: it costs an embedding and can outrank the span it duplicates.
func TestNoWindowIsContainedInAnother(t *testing.T) {
	for _, n := range []int{6, 7, 8, 11, 12} {
		got, err := Chunks("a.txt", lines(n), winOpts(5, 3))
		if err != nil {

				t.Fatalf("%d lines: window %d (%d..%d) adds nothing over %d..%d",

			}
		}
	}

```go
// Package chunk cuts one file into the retrievable regions a span is made of.
//
// Chunking takes a Strategy, not just a fallback. The eval (spec §9) compares
// AST spans against fixed windows over the *whole* corpus, so "window" has to
// be a thing a caller can ask for, not only what happens when the parser
// fails. Without that the baseline arm cannot be built and the headline
// comparison has nothing to compare against.
package chunk

type Strategy string

const (
	StrategyAST    Strategy = "ast"
	StrategyWindow Strategy = "window"
)

// Options are line-valued, not byte-valued. A span is cited by line range, so
// a byte window would have to account for lines anyway to name its range, and
// its boundaries would land mid-line where no citation can point.
type Options struct {
	Strategy      Strategy
	WindowLines   int
	WindowOverlap int
	// MaxDeclLines is where a declaration stops being one unit. Over it, the
	// declaration is sub-windowed: one generated 3,000-line file must not
	// become a single useless span (spec §5).
	MaxDeclLines int
}

func Defaults() Options {
	return Options{Strategy: StrategyAST, WindowLines: 40, WindowOverlap: 10, MaxDeclLines: 200}
}

func (o Options) Validate() error {
	switch o.Strategy {
	case StrategyAST, StrategyWindow:
	default:
		return fmt.Errorf("chunk: unknown strategy %q", o.Strategy)
	}
	if o.WindowLines <= 0 {
		return fmt.Errorf("chunk: WindowLines must be positive, got %d", o.WindowLines)
	}
	if o.WindowOverlap < 0 || o.WindowOverlap >= o.WindowLines {
		return fmt.Errorf("chunk: WindowOverlap must be in [0,%d), got %d", o.WindowLines, o.WindowOverlap)
	}
	if o.MaxDeclLines <= 0 {
		return fmt.Errorf("chunk: MaxDeclLines must be positive, got %d", o.MaxDeclLines)
	}
	return nil
}

// Chunks cuts src according to opt. filename is what the parser reports in an
// error and what decides whether the AST strategy tries at all; nothing is
// read from disk.
//
// It returns an error only for an invalid Options. A file that will not parse
// is not an error here — it is the window fallback, which is the whole point.
func Chunks(filename string, src []byte, opt Options) ([]Chunk, error) {
	if err := opt.Validate(); err != nil {
		return nil, err
	}
	ls := splitLines(src)
	if len(ls) == 0 {
		return nil, nil
	}
	if opt.Strategy == StrategyWindow {
		return windows(ls, 1, len(ls), opt), nil
	}
	return astChunks(filename, src, ls, opt), nil // Task 2
}
```

```go
// splitLines returns src's lines without their terminators, and nothing at all
// for a file that is empty or only whitespace. Text is rebuilt from these, so
// a chunk's Text is by construction exactly the lines its range names.
func splitLines(src []byte) []string {
	if len(strings.TrimSpace(string(src))) == 0 {
		return nil
	}
	s := strings.TrimSuffix(string(src), "\n")
	return strings.Split(s, "\n")
}

// windows tiles [from,to] — 1-based inclusive, indices into ls — with fixed
// windows of opt.WindowLines striding by WindowLines-WindowOverlap.
//
// It is used for three things, which is why it takes a range rather than a
// file: the whole file under StrategyWindow, one unparseable file under
// StrategyAST, and one over-long declaration under either.
func windows(ls []string, from, to int, opt Options) []Chunk {
	stride := opt.WindowLines - opt.WindowOverlap
	// Validate rejects an overlap >= size, which is the only way to get here
	// with a stride that does not advance. Refusing rather than trusting that
	// keeps a caller that skipped Validate from tiling forever.
	if stride <= 0 {
		return nil
	}
	var out []Chunk
	for start := from; start <= to; start += stride {
		end := min(start+opt.WindowLines-1, to)
		out = append(out, Chunk{
			Kind:      models.KindFile,
			StartLine: start,
			EndLine:   end,
			Text:      strings.Join(ls[start-1:end], "\n"),
		})
		// The stride would emit a window ending here again, and a window
		// wholly inside its predecessor is a duplicate document competing
		// with the span it duplicates.
		if end == to {
			break
		}
	}
	return out
}
```

### Task 2: The AST chunker

One span per top-level declaration, carrying its doc comment, with two ways out: a file that will not parse or is not Go becomes windows, and a declaration over `MaxDeclLines` becomes sub-windows. Both are `kind=file` (spec §5).

**Files:**
- Create: `packages/shared/chunk/ast.go`, `packages/shared/chunk/testdata/decls.gotxt`, `packages/shared/chunk/testdata/broken.gotxt`
- Test: `packages/shared/chunk/ast_test.go`

**Interfaces:**
- Consumes: Task 1's `Options`, `Chunk`, `windows`, `splitLines`; `go/parser`, `go/ast`, `go/token`.
- Produces: `func astChunks(filename string, src []byte, ls []string, opt Options) []Chunk` (unexported; `Chunks` is the surface).

**Decisions, with their reasoning:**

- **One span per top-level `ast.Decl`**, which is what spec §5 says. A parenthesised `const (...)` block is therefore one span, and its `Symbol` is the first name declared in it so the lexical arm can still find it. The alternative — one span per `ValueSpec` — gives the eval's generated golden set more cases but splits a block whose doc comment describes the block as a whole. Recorded in Open Questions; revisit in P6 if the golden set turns out thin.
- **`import` declarations are skipped.** An import block is not a retrievable unit and it is the one declaration whose text is identical across thousands of files, so it would be a bank of near-duplicate vectors competing with real answers.
- **A method's `Symbol` is `Recv.Method`** (`Store.PutRepo`), using the receiver's base type name with any `*` and type parameters dropped. That is how the symbol is searched for and how P4's `symbols` table will name it.
- **The span starts at the doc comment when there is one** — spec §5 says the span carries it — and at the declaration keyword otherwise.
- **Sub-windows carry `Kind=KindFile` and an empty `Symbol`.** The golden set maps one symbol to one correct span; a symbol repeated across N sub-windows would give a question N correct answers, and hit@k would silently measure something else. The cost is that a 3,000-line function is not findable by name, which is recorded rather than hidden.
- **Text comes from the line range, not from `src[decl.Pos():decl.End()]`.** The two differ, and the invariant worth keeping is `Text == the lines the citation names`.

```go
// astChunks returns one chunk per top-level declaration, or windows over the
// whole file when it is not Go or will not parse.
//
// SkipObjectResolution: nothing here needs the resolver's identifier links,
// and spec §7 is explicit that chunking uses no type information.
func astChunks(filename string, src []byte, ls []string, opt Options) []Chunk {
	if !strings.HasSuffix(filename, ".go") {
		return windows(ls, 1, len(ls), opt)
	}
	fset := token.NewFileSet()
	f, err := parser.ParseFile(fset, filename, src, parser.ParseComments|parser.SkipObjectResolution)
	if err != nil {
		return windows(ls, 1, len(ls), opt)
	}

	var out []Chunk
	for _, d := range f.Decls {
		kind, symbol, ok := classify(d)
		if !ok {
			continue
		}
		start := line(fset, d.Pos())
		if doc := docOf(d); doc != nil {
			start = line(fset, doc.Pos())
		}
		// End() is one past the declaration's last byte, which for a decl
		// closing with "}" is the newline on the same line — so this is the
		// last line the declaration occupies, inclusive.
		end := line(fset, d.End())
		if end-start+1 > opt.MaxDeclLines {
			out = append(out, windows(ls, start, end, opt)...)
			continue
		}
		out = append(out, Chunk{
			Kind: kind, Symbol: symbol,
			StartLine: start, EndLine: end,
			Text: strings.Join(ls[start-1:end], "\n"),
		})
	}
	return out
}
```

`line` is `fset.PositionFor(pos, false).Line`, **not** `fset.Position(pos).Line`. `Position` applies `//line` directives, so a generated file carrying `//line sample.y:3000` reports lines this file does not have — a citation into the generator's source, and a slice past the end of `ls`. Measured on a six-line file: `Position` gives `3000..3002`, `PositionFor(..., false)` gives `4..6`, and the adjusted form panics with `slice bounds out of range [:42] with capacity 6`. Physical lines are what a citation names, so no clamp on `end` is needed and none is written.

`classify` returns `false` for an import block and for anything the closed `SpanKind` set does not name; `docOf` reads `*ast.FuncDecl.Doc` or `*ast.GenDecl.Doc`. The symbol for a `GenDecl` is the first name of its first spec; for a method it is `recvBase(d.Recv) + "." + d.Name.Name`, where `recvBase` unwraps `*ast.StarExpr` and `*ast.IndexExpr`/`*ast.IndexListExpr` (a generic receiver, `func (s *Stack[T]) Push`) down to the `*ast.Ident`.

### Task 3: Doc-comment stripping, as a source pre-pass

Spec §5, and the easiest thing in this phase to get wrong. The eval's golden set is "doc-comment prose → the symbol it documents". If doc comments stay in span text, the query is a literal substring of the correct answer, both arms score near-perfectly on string overlap, and the experiment measures nothing — `grep` wearing a benchmark's clothes.

**The design question is how one chunker serves both corpora without duplicating itself. The answer is that stripping is not a chunker mode at all.** It is a transform on the source bytes, applied before either strategy:

```go
stripped, err := chunk.StripDocs(path, src)        // path decides whether it parses at all
chunks, err := chunk.Chunks(path, stripped, opt)   // opt.Strategy is orthogonal
```

Three things fall out of that, all of them load-bearing:

1. **Both arms get literally identical input bytes.** "Both arms get identical treatment" stops being a discipline the eval runner has to remember and becomes a property of where the call sits.
2. **`Window` still never parses** (spec §5). The pre-pass parses; the strategy does not. This is a deliberate reading of §5 and it is called out in Open Questions, because §5's two sentences — "Window never parses at all" and "the eval indexes a corpus with doc comments stripped" — cannot both be true of a single function that does its own stripping.
3. **Line numbers must not move.** So `StripDocs` **blanks** doc comments rather than deleting them: every byte of a doc comment except its newlines is dropped, leaving empty lines behind. Line count and every line number are preserved exactly, the window arm's windows land on exactly the same lines as they would on the unstripped file, and a span's text is still exactly the lines it names — of the source that was actually indexed.

   **Measured correction to that last claim.** The AST arm's declaration *ranges* are not unchanged, and cannot be. A blanked doc comment is no longer a comment, so `docOf` finds nothing and the parser starts the declaration at its keyword: in `docs.gotxt`, `Counter.Add` goes from 37..46 to 40..46 and `KindA` from 18..29 to 25..29. What is invariant is `EndLine` — nothing below a blanked comment moves — and the window arm's ranges, which are byte-identical. That is the property the design is for; the start line sliding down onto real code costs the span nothing but leading blanks.

- [ ] **Step 2: Implement `strip.go`**

```go
// StripDocs blanks every doc comment in src, keeping its newlines so no line
// number moves.
//
// It exists for the eval (spec §5). The golden set's questions are doc-comment
// prose and its answers are the spans those comments document, so a corpus
// that keeps the comments makes every question a substring of its own answer
// and both arms score on string overlap. The production index keeps them,
// because there they are the best signal available.
//
// A pre-pass rather than a chunker mode: applied before Chunks, both eval arms
// chunk byte-identical input, and StrategyWindow still never parses.
//
// Blanked, not deleted: deleting lines would move every line number below the
// comment, and the window arm's windows would then cover different lines than
// the AST arm's declarations.
func StripDocs(filename string, src []byte) ([]byte, error) {
	if !strings.HasSuffix(filename, ".go") {
		return src, nil
	}
	fset := token.NewFileSet()
	f, err := parser.ParseFile(fset, filename, src, parser.ParseComments|parser.SkipObjectResolution)
	if err != nil {
		return nil, fmt.Errorf("chunk: strip %s: %w", filename, err)
	}

	tf := fset.File(f.Pos())

	// drop[i] is true for a byte of doc prose. A mask rather than a list of
	// ranges so the traversal below can visit them in any order.
	drop := make([]bool, len(src))
	add := func(g *ast.CommentGroup) {
		if g == nil {
			return
		}
		for _, c := range g.List {
			if isDirective(c.Text) {
				continue
			}
			// Not tf.Offset(c.End()): End() is Slash+len(c.Text) and
			// go/scanner strips carriage returns out of c.Text, so on a
			// CRLF file it lands inside the comment. commentEnd scans the
			// raw bytes forward to "*/", or to "\n" for a // comment.
			start := tf.Offset(c.Pos())
			for i := start; i < commentEnd(src, start); i++ {
				drop[i] = true
			}
		}
	}
	// f.Doc is not reached by Inspect's switch below, and it is the largest
	// single block of prose in a well-documented file.
	add(f.Doc)
	ast.Inspect(f, func(n ast.Node) bool {
		switch d := n.(type) {
		case *ast.FuncDecl:
			add(d.Doc)
		case *ast.GenDecl:
			add(d.Doc)
		case *ast.TypeSpec:
			add(d.Doc)
		case *ast.ValueSpec:
			add(d.Doc)
		case *ast.ImportSpec:
			add(d.Doc)
		case *ast.Field:
			add(d.Doc)
		}
		return true
	})

	out := make([]byte, 0, len(src))
	for i, b := range src {
		// The line terminator is what is kept: it is the whole of "blanked,
		// not deleted", and only a /* */ doc comment has any inside it.
		// Under CRLF the terminator is both bytes.
		if drop[i] && b != '\n' && b != '\r' {
			continue
		}
		out = append(out, b)
	}
	// Re-parses its own output and compares newline counts. One extra parse
	// in a pre-pass that already parses once, against a corruption that is
	// otherwise silent — see the CRLF paragraph below.
	if err := selfCheck(filename, src, out); err != nil {
		return nil, err
	}
	return out, nil
}
```

**The CRLF bug, found in the P2 review round.** As first written this loop trusted `ast.Comment.End()`, which is `Slash + Pos(len(c.Text))` — and `go/scanner.scanComment` strips carriage returns *out of* `c.Text`. For `"package p\r\n\r\n/*\r\nDoc for F.\r\nMore prose.\r\n*/\r\nfunc F() {…"`, `len(c.Text)` is 10 against 12 raw bytes, so the blanking under-covered by two, the output kept a bare `*/`, and it no longer parsed (`crlf.go:6:1: expected declaration, found '*'`). `StripDocs` returned **no error**, and because the AST arm's answer to source it cannot parse is windows, `chunk.Chunks` over the stripped bytes answered `file/` instead of `func/F` — the arm changed and nothing said so. A bare `\r` inside a `//` comment is the same defect one byte at a time: `"// a\rb prose"` left an `e` behind.

That is why `selfCheck` exists. This class of bug is invisible exactly where it is worst — a corrupted corpus looks like a healthy run — so the pre-pass verifies its own output rather than assuming it. It is the same argument as the parse-failure refusal above, applied to the output instead of the input.

`isDirective` is go/ast's own rule, reproduced: the three grandfathered words `line `, `extern `, `export `, then `//name:value` where `name` is lowercase alphanumeric with no space. The lowercase test is not cosmetic — it is what keeps prose like `// todo:fix this` from reading as a directive and surviving into the eval corpus. **Corrected in the P2 review round:** `// TODO: explain this.` cannot show that, because it is refused twice over — the name segment holds a space *and* so does the character after the colon — so it discriminates neither check. See M10 and M16–M19 below. **`go/ast` keeps its own `isDirective` unexported: re-verified at Go 1.27.0, `go doc go/ast.IsDirective` answers `no symbol IsDirective in package go/ast`** (`ast.IsGenerated` does exist and is a different thing).

A byte mask, not the `inAny` linear scan the plan first sketched: the mask is O(len(src)) instead of O(len(src)·comments) and needs no assumption about traversal order. Do not justify it as guarding against duplicate or nested doc groups — measured, go/parser attaches a doc comment to exactly one node, including for single-spec parenthesised `type (…)` and `var (…)` blocks.

Offsets come from the `token.File`, not from `fset.Position`. That is a preference, not a safeguard: M11 measures the swap and every test still passes, because a `//line` directive moves the *line* a position reports and never the byte offset. The `//line` hazard Task 2 hit is line-valued only.

**The fake is a hashed bag of words, not a hash of the text.** A hash gives two distinct texts near-orthogonal vectors, which is enough to prove "no error" and nothing else: hit@k would be noise and no end-to-end retrieval assertion could be written. Feature-hashing the tokens instead gives real lexical similarity, deterministically and with no dependency, so Task 7 can assert that a query drawn from a span retrieves *that* span. The cost is that the fake's numbers look like lexical overlap — which is exactly why spec §9's banner says the figures a CI run prints are not quality. The banner is not decoration; it is describing this.

// A fake that drifted would make the CI eval's numbers unreproducible and the
// mechanics check would be measuring the fake.
func TestFakeIsDeterministic(t *testing.T) {
	a, b := NewFake(768), NewFake(768)
	x, err := a.Embed(context.Background(), []string{"func (s *Store) PutSpans"})
	if err != nil {
		t.Fatal(err)
	}
	y, err := b.Embed(context.Background(), []string{"func (s *Store) PutSpans"})
	if err != nil {
		t.Fatal(err)
	}
	if !reflect.DeepEqual(x, y) {
		t.Fatal("two Fakes gave different vectors for the same text")
	}
}

func TestFakeVectorsAreUnitLengthAndTheRightWidth(t *testing.T) {
	got, err := NewFake(768).Embed(context.Background(), []string{"alpha beta", "gamma"})
	if err != nil {
		t.Fatal(err)
	}
	for i, v := range got {
		if len(v) != 768 {
			t.Fatalf("vector %d has width %d, want 768", i, len(v))
		}

		}

		}
	}

// The job's deadline has to reach the HTTP call, or a hung model outlives the
// job that owns it.
func TestOllamaHonoursContextCancellation(t *testing.T) {
	// The handler MUST drain the request body before blocking, and the test
	// MUST release it before closing the server. Measured on Go 1.27: written
	// as `<-r.Context().Done()` alone this test hangs until the package
	// timeout. net/http starts the background read that notices a
	// disconnected client only once the request body hits EOF, so a handler
	// that never reads the body never wakes, and srv.Close() waits on it
	// forever. Probed both ways: undrained, the handler's context was still
	// live 4s after the client gave up; drained, it was cancelled in 50ms.
	release := make(chan struct{})
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		io.Copy(io.Discard, r.Body)
		select {
		case <-r.Context().Done():
		case <-release:
		}
	}))
	defer srv.Close()
	defer close(release)
	ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
	defer cancel()
	start := time.Now()
	_, err := NewOllama(srv.URL, "m", 768, time.Minute).Embed(ctx, []string{"x"})
	if err == nil {
		t.Fatal("want a deadline error")
	}
	if elapsed := time.Since(start); elapsed > 5*time.Second {
		t.Fatalf("returned after %v; the context did not reach the request", elapsed)
	}
}

Independent of Tasks 1–4. The `spans` table already exists with every column this needs (`0001_init.sql`), including `vector(768)` and the HNSW index from `0002`. **No migration is needed and none should be written.**

**Files:**

- Test: `packages/shared/store/spans_live_test.go` (`//go:build live`), `packages/shared/store/spans_test.go` (hermetic, for the id and the vector literal)

**Interfaces:**
- Produces:
  - `func SpanID(repoID, path string, start, end int, digest string) string`
  - `func Digest(text string) string`
  - `type EmbeddedSpan struct { models.Span; Embedding []float32 }`
  - `func (s *Store) PutSpans(ctx context.Context, repoID string, spans []EmbeddedSpan, model string, dim int) error`
  - `func (s *Store) CountSpans(ctx context.Context, repoID string) (int, error)`

**Decisions, with their reasoning:**

- **`SpanID = hash(repoID, path, start, end, digest)`**, exactly spec §3, reusing `repos.go`'s existing `hash` helper and its NUL separator. Integers go in as `strconv.Itoa`, so `(1, 23)` and `(12, 3)` cannot collide — the separator already guarantees that, and a test pins it.
- **`Digest` is the full SHA-256 hex of the text**, not the 16-byte truncation the ids use. An id needs to be short and unique within a repo; a digest is the thing spec §8 says proves the retrieved text is the indexed text, and truncating it weakens that for no gain.
- **`PutSpans` is authoritative for the repo: it deletes the repo's spans and writes the given set, in one transaction.** `PutRepo` chose upsert-only and recorded the consequence — a second index producing fewer rows leaves the first run's behind. For spans that consequence is worse than untidy: re-chunking the same commit under a different strategy or window size would leave both runs' spans in one table, and a retrieval would silently mix the two arms of the experiment. The contract is therefore "these are all of this repo's spans", stated in the doc comment and pinned by a test that writes a smaller second set and counts.
- **Vectors are sent as pgvector's text literal with an explicit `$n::vector` cast.** No pgvector Go binding, so no new dependency; `strconv.FormatFloat(f, 'f', -1, 32)` round-trips a float32 exactly.
- **The width is checked in Go before the write.** Postgres would reject it too, but its message is about a column and the Go one can say which span and which model.

- [ ] **Step 3: Implement**

`PutSpans` opens a transaction, `DELETE FROM spans WHERE repo_id = $1`, then sends the inserts through `pgx.Batch` in chunks (start at 500 per batch). **`$12` is wrong: `spans` has thirteen columns** (id, repo_id, file_id, path, kind, symbol, start_line, end_line, text, digest, embed_model, embed_dim, embedding), so the statement is `VALUES ($1,…,$13::vector)`.

**The reason this plan gives for checking widths before the transaction is false, and was measured false.** `defer tx.Rollback(ctx)` undoes the DELETE, so a check *inside* the transaction loses nothing either — see M5. Check before it anyway, but for the reason that survives the counterfactual: a mis-configured embedder then fails without a round trip, and with a message naming the span rather than a column. What actually keeps the previous spans safe is the transaction, and the test that pins it must make the write fail *inside* the batch (a span whose `file_id` does not exist), because that is the case no pre-flight check can reach.

Depends on Tasks 1–5. **This is the task P1's mutation coverage would have missed:** constructors and wiring were its blind spot, because mutation coverage only covers what you point it at. So the mutations here are aimed at `main` and `runJob`, not at the packages they call.

**Files:**
- Modify: `apps/indexer/internal/walk/walk.go` (export the guarded reader), `apps/indexer/cmd/main.go`, `Makefile`
- Create: `apps/indexer/cmd/embed.go` (embedder construction), `apps/indexer/cmd/content.go` (read, blob hash, indexability)
- Test: `apps/indexer/cmd/main_test.go` (extend), `apps/indexer/cmd/content_test.go`, `apps/indexer/internal/walk/walk_test.go` (extend)

**Interfaces:**
- Consumes: `chunk`, `embed`, `store.PutSpans`, `walk.ReadRegular`.
- Produces: no new exported API outside `walk.ReadRegular` / `walk.ErrSkipped`.

**Decisions, with their reasoning:**

- **The second read goes through the walker's guarded reader.** The walk reads every file to count its lines and then throws the bytes away, so the chunker has to read them again. Reading them with a plain `os.ReadFile` would reintroduce exactly the hole P1 closed: a symlink swapped in after the walk would be followed, and the fixture test that proves the walker does not follow links would still pass. `readRegular` is therefore renamed `ReadRegular` and exported with its `O_NOFOLLOW|O_NONBLOCK` + `fstat` intact, and the indexer calls it. The alternative — a callback that hands the body to the caller while the descriptor is open — is one read instead of two and closes the window entirely, but it rewrites the walker's tested surface; recorded in Open Questions.
- **`files.blob` is filled here.** P1 left the column empty and wrote "P2 fills it when it needs content addressing for incremental re-index" — but incremental re-index is P7, so the real reason is simpler: the chunk pass already has the bytes in hand, and computing git's blob hash from them costs one SHA-1 over content that is already read. Spec §3 says the column is git's own content hash, so it is git's own: `sha1("blob " + len + "\x00" + content)`, verified against `git hash-object`.
- **A file is chunked only if it is text.** Two reasons, one of them fatal rather than aesthetic: Postgres `TEXT` refuses a value that is not valid UTF-8 *and* refuses an embedded NUL, so a repository containing a PNG would fail the whole job on the span insert. The cost reason is secondary: a minified bundle or a binary blob has nothing retrievable and costs an embedding call each. The rule is `utf8.Valid(body) && !bytes.ContainsRune(body, 0) && f.Lang != ""`. The `Lang != ""` half is a deviation from a literal reading of spec §5 and is in Open Questions.
- **One deadline for the whole job.** Spec §6 requires this for the type-check stage and the same argument applies now: `runJob` derives one context from `JOB_DEADLINE_SECONDS` covering clone, read, chunk, embed and write, so a slow clone cannot buy itself extra time by failing into the embedder. It also closes the gap P1 recorded — `walk.Files` had no deadline of its own.
- **Recording a failure uses a fresh context.** The job context is the one that just expired; using it to write the failure means the write fails too and the job stays `leased` until the lease expires. A separate short-deadline context derived from the *process* context is what makes a timed-out job reach `failed`.
- **Files are written before spans.** `spans.file_id` references `files(id)`, so the order is a constraint, not a preference — and Task 5's foreign-key test is what makes that a fact rather than a claim.

## Open questions

Nothing here is blocking. Each is something the spec does not settle, with the tradeoff and a recommendation, so a reviewer can disagree with a decision rather than discover it.

1. **The embedding model.** Spec §3 fixes the width at 768 and names no model. `0001_init.sql`'s comment says `nomic-embed-text` and compose ships Ollama, so the decision has effectively been made in a comment rather than in the spec.
   *Recommendation:* `nomic-embed-text` over Ollama's `/api/embed`, verified against the pinned image before the client is written. `embed_model` and `embed_dim` sit on every span row, so a later switch is detectable in the data rather than inferred from a deploy date. The cost of being wrong is a re-index, not a migration.

2. **Window size and overlap.** Spec §5 says "fixed windows" and gives no numbers.
   *Recommendation:* **40 lines, 10 overlap**, both configurable. 40 lines of Go is roughly 400–500 tokens — comfortably inside the embedder's context and close to the median top-level declaration, so neither arm is handicapped by chunk size and the comparison is about *where the cuts fall* rather than how much text each side gets. 25% overlap is the usual hedge against a declaration cut in half and costs about a third more spans. Knobs, so P6 can sweep them and report rather than assert.

3. **The sub-windowing threshold.** Spec §5 says "longer than a threshold" and names none.
   *Recommendation:* **200 lines.** A 200-line top-level declaration is already an outlier in hand-written Go, so the path fires on generated code and large tables and essentially never on ordinary code — which is what §5's "3,000-line file" example describes. Much lower and the AST arm quietly becomes the window arm; much higher and a generated file is one useless span again.

4. **Grouped declarations: one span per `Decl`, or one per `Spec`.** Spec §5 says "one span per top-level declaration", which is the `Decl`. But a parenthesised `const (…)` or `var (…)` block can carry a doc comment per spec, and §9 generates one golden question per *exported symbol carrying a doc comment* — so per-`Decl` maps several questions onto one span.
   *Recommendation:* **per-`Decl` now**, as the spec literally says, with `Symbol` set to the first name in the block so it stays findable. Revisit in P6 with a count: if a meaningful share of generated questions land on grouped blocks, split per-spec then, with evidence.

5. **What gets chunked at all.** Spec §5 says a file that "is not Go" is windowed, which read literally covers every regular file the walker returns — `package-lock.json`, a PNG, a minified bundle.
   *Recommendation:* **skip files whose `Lang` is empty, and any file whose bytes are not valid UTF-8 or contain a NUL.** The second half is not a preference: Postgres `TEXT` refuses both, so without it one binary file fails an entire job. The first half is a cost and quality call — a lockfile has nothing retrievable and each one costs an embedding call. The deviation is visible in `walk.langByExt`, which classifies nine extensions today, so widening it is a one-line change if P3's retrieval wants more.

6. **Where the eval's two arms live.** Worth a reviewer's attention. `RepoID = hash(remote_key, commit)` and `SpanID = hash(repo, path, start, end, digest)` — neither has room for a strategy. Indexing the same commit twice, once per arm, writes into the *same* `repos` row, and an AST span and a window span of the same file with the same range and text collide on the primary key. `PutSpans` deleting the repo's spans before writing means the second arm silently replaces the first.
   *Recommendation:* the eval runs each arm against **its own database** (the evalrunner takes a DSN per arm). That keeps §3's id formulas exactly as written and keeps the stripped and unstripped corpora from ever mixing. The alternatives are a `strategy` column plus a changed id formula — a deviation from §3 in the one place §3 calls a testable property — or synthesising a fake remote per arm, which puts a lie in `repos.remote`. P6 decides; P2 only has to avoid foreclosing it, and delete-then-write does not.

7. **The symbol on a sub-window.** Recommendation is an empty `Symbol`, so a golden question has exactly one correct span rather than N. The cost is that a 3,000-line function is not findable by name in the lexical arm. If P3's lexical arm shows that mattering, the fix is a `symbols` row pointing at the first sub-window — P4's table anyway.

8. **One read or two.** The chunk pass re-reads every file the walk already read. Recommendation is two guarded reads: the alternative — a callback handing the body to the caller while the descriptor is open — rewrites `walk.Files`'s tested surface for a saving invisible at the current caps, though it would also close the swap window between the two reads that the current design only narrows. Revisit if a profile says so, not on the strength of this paragraph.

## What the spec leaves underspecified or in tension

Recorded so a reviewer sees them as findings rather than as choices made quietly.

- **§5 contains a tension it does not resolve.** "`Window` never parses at all" and "the eval indexes a corpus with doc comments stripped" cannot both hold of a chunker that does its own stripping, because finding Go doc comments requires parsing. This plan resolves it by making stripping a source pre-pass whose output both strategies see. **Confirmed in Task 3 by measurement:** the window arm's ranges over `docs.gotxt` are byte-identical stripped and unstripped, and deleting the comments instead of blanking them collapses six windows to four. The alternative — window-arm text keeping its doc comments — would make the two arms incomparable in exactly the way §5 exists to prevent.
- **`kind=file` is not a reliable label for which arm produced a row.** `models.go` used to say "the eval harness compares AST spans against exactly this", but §5 also makes sub-windowed declarations and unparseable files `kind=file` under the *AST* strategy. An AST run over a repository of generated code therefore produces rows indistinguishable from the baseline arm's. The arm is a property of the run, not of the row, and P6 must not infer it from `kind`. **The review round fixed both copies of the claim** — `models.go`'s and the one this plan had prescribed for `TestWindowsAreKindFile` — after the first correction pass fixed this paragraph and left the comments it had dictated standing.
- **Stripping can change how a declaration chunks, not only where its span starts.** `TestStrippedSourceStillChunksToTheSameDeclarations` states its equality unconditionally; it is that fixture's. Measured in the review round: a declaration 201 lines long *including* a four-line doc comment is 7 sub-windowed `kind=file` chunks unstripped (3..203) and a single `kind=func` span stripped (7..203), because blanking drops it under `MaxDeclLines`. Inside the eval this cannot bite — the corpus is stripped once and both arms chunk the same bytes — but P6 cannot harvest gold spans from unstripped source and expect them to name the stripped corpus's rows.
- **P1 deferred `files.blob` to "P2 … for incremental re-index", but incremental re-index is P7** (§13). P2 fills it anyway, for a better reason: the chunk pass already holds the bytes.
- **The Makefile's `OLLAMA_URL` default was `http://localhost:11434`; compose publishes Ollama on `11435`.** Fixed in Task 6. The predicted symptom — a connection refused — is not what happens on a machine that also has Ollama installed on the host, which is the common case for anyone who tried the model before running compose: measured here, `11434` answered `{"version":"0.33.0"}` and served embeddings. The corpus would then be embedded by a daemon compose neither pins nor manages, and nothing about the run would look wrong.

- **Compose pinned `ollama/ollama:latest`, which this plan twice called "the pinned image".** Fixed in Task 6 to `ollama/ollama:0.33.0@sha256:08ddf4b4dbfdc4fc1f5b0fe535915998581085402e307b57bb308db68460e372`. Not hypothetical: measured on the same day, `latest` already resolved to `sha256:020e4134…` while the container this project's numbers came from was 0.33.0. A `docker compose pull` would have re-embedded the whole corpus under a different model between two runs of the same command.
- **Nothing in the spec says whether embedding shares the job's wall-clock budget.** §6 says the type-check stage does — "one deadline for the whole job, not a fresh one per stage". P2 applies the same rule to chunk and embed, which also closes the gap P1 recorded where `walk.Files` had no deadline at all.

## The whole-branch review round

A review of all 25 commits at once, after Task 7. Four findings, all measured before and after; the counts in the README were re-measured and are unchanged.

1. **The eval's baseline arm could not be built at all.** `CHUNK_STRATEGY=window STRIP_DOC_COMMENTS=true EMBED_PROVIDER=fake` over `rs/zerolog` failed the whole job — `embedding spans 576-607: embed: text 19 has no tokens to hash`, three attempts to terminal, **0 repos and 0 spans written**. The chain crosses four tasks, which is why no per-task review caught it: Task 3 blanks `log.go`'s ~100-line package comment, Task 1's tiler emits three windows that are entirely blank lines, Task 4's fake refuses a text with no tokens, Task 6 propagates that as a whole-job failure. The AST arm was unaffected, so the eval looked half-runnable. Production had the same root with nothing bounding it: any indexable file with 40 consecutive lines holding no letter or digit fails its repository.

   **Fixed in `chunk`, not before the embedder.** A region with no word in it is not a retrievable region, which is what this package is defined to emit — so both arms drop the same regions by construction, and an AST arm keeping a sub-window the baseline arm dropped cannot bias the one comparison §9 exists to make. Dropped rather than embedded: Ollama does answer a whitespace-only text with a unit vector (measured, 768 wide, norm 1.0000002), but `'[0,0,0]'::vector <=> '[1,2,3]'::vector` is `NaN` in pgvector (measured against pg17), so a zero-vector fallback would corrupt ranking silently. `Chunks` returns the count so the compiler makes every caller acknowledge it, and the indexer logs a per-job `tokenless` total beside `vanished` and `unstrippable`.

   Measured after, same command: **768 spans**, `tokenless=3` — `log.go:1-40`, `31-70` and `61-100`, exactly the windows inside its package comment. The AST arm on the stripped corpus is 1,303 either way, and production is unchanged at 1,303 and 771.

2. **`go test -tags=live ./...` emptied the database it was pointed at.** `evict_live_test.go` ran `DELETE FROM repos` with no `WHERE` on entry and on exit and `jobs_live_test.go` did the same to `jobs` — against the DSN the README tells a reader to use. Measured with a canary in the dev database: repos, files and jobs all went 1 → 0 while both suites printed `ok`. Every live suite now creates a database of its own through `packages/shared/testdb` and drops it afterwards; the base DSN is only ever connected to in order to issue those two statements. A test in `store` and one in `jobs` compare `current_database()` against the name `DATABASE_URL` carries, so pointing them back at it fails rather than destroys.

3. **A skipped `-tags=ollama` run printed `ok`.** The CI guard was present and does fire, but nothing in CI runs that tag. Asking for the tag is already a statement that a server is meant to be there, so an unset `OLLAMA_URL` now fails whether `CI` is set or not. The `live` tag keeps the CI-variable form: `go test -tags=live ./...` is a routine command with nothing to point it at.

4. **Two of the ten knobs were not validated at boot**, against a README sentence that said all ten were. `OLLAMA_URL='not a url at all' EMBED_MODEL='no-such-model-xyz'` logged `indexer up` and failed on the first leased job's embed call, spending an attempt for a setting no retry can fix. `newEmbedder` now parses `OLLAMA_URL` (`url.Parse` accepts `not a url at all` as a relative path, so the scheme and host are what decide) and embeds one short text at boot on its own 30s deadline — `JOB_DEADLINE_SECONDS` defaults to 600, and a worker that hangs that long without saying why it did not start is worse than one that refuses. The fake is not probed, so CI and the live suites still need no model anywhere.

**Mutations run in this round: 11 applied, 10 kills by assertion, 1 void.** The void was `hasTokens` rewritten to `return true` with the loop deleted — an unused import, so it tested the compiler; rewritten as "whitespace counts as a token", it kills. The kills: the drop removed entirely (window and AST tests, plus the end-to-end job failing exactly as it did in production); the drop applied to the window arm only (AST test alone, which is the arms-agree property); the count hard-wired to zero (both chunk tests and the log assertion); `tokenless` left out of the warn gate (the log assertion alone); `OLLAMA_URL` parsing removed (three subtests, whose messages then name a transport error instead of the setting); the boot probe removed, and the probe swallowing its error (both leave a bad model and a dead server booting).
